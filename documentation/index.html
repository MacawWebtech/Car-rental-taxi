Getting started

Unzip the package and open pages/index.html, or serve the folder with any static server (npx serve ., python3 -m http.server). There is no build step: every page is plain HTML using Bootstrap 5.3 and three small vanilla JavaScript files.

Every page loads style.css, dark-mode.css and rtl.css, then main.js. The booking pages add booking.js; the dashboards add dashboard.js.

Folder structure

assets/css      style.css · dark-mode.css · rtl.css
assets/js       main.js · booking.js · dashboard.js · plugins/
assets/images   your WebP images
assets/fonts    optional self-hosted fonts
pages/          16 website pages
dashboard/      9 admin pages
documentation/  this file

Pages

Website: index (Home 1 — mobility services), home-2 (chauffeur & corporate, editorial layout), about, services, service-details (airport transfer), fleet, vehicle-details, booking (5-step), pricing, locations, contact, login, register, user-dashboard, 404, coming-soon.

Admin: dashboard/index (overview), bookings, vehicles (with add/edit modal), drivers, customers (with profile panel), payments (with invoice preview), messages, reports, settings.

Colours, fonts & spacing

All design tokens are CSS custom properties at the top of style.css:

--k-ink: #15171A;        /* charcoal — text, dark sections */
--k-ivory: #F5F2EA;      /* warm alternate background */
--k-amber: #D4A24C;      /* accent — buttons, highlights */
--k-amber-deep: #8F6419; /* accent for text on light (WCAG AA) */
--k-steel: #8C9299;      /* metallic grey */
--r-sm / --r-md / --r-lg /* 4 / 8 / 14px radii */
--font-ui: Manrope; --font-serif: DM Serif Display;

Dark mode overrides the same variables under [data-bs-theme="dark"] in dark-mode.css.

Dark mode

The toggle (.theme-toggle) saves the choice to localStorage key mobility-theme. With no saved choice the OS preference is used. A tiny inline script in each <head> applies the theme before first paint so there is no flash. dashboard.js redraws charts on the themechange event.

RTL & languages

The language menu uses [data-lang] items and stores the choice in mobility-lang. Arabic (ar) and Hebrew (he) switch the document to dir="rtl". The template ships in English: to translate, duplicate the pages per language or connect your i18n system; the RTL layout is handled by rtl.css and logical CSS properties.

Booking widget & fares

The widget ([data-booking-widget]) has accessible tabs for Taxi, Rental and Hourly. Each pane is a form; the live estimate updates on input. Fares come from estimateFare() in booking.js using the RATES table and 5% GST. The demo distance is a stable pseudo-value — replace demoDistance() with the Google Distance Matrix API.

The booking page (#bookingFlow) validates each step, updates the summary card and opens a confirmation modal at the end. Query parameters from the widget (pickup, drop, date, time, vehicle) are pre-filled.

Forms & validation

Add data-validate-form to any form. Required fields, type="email" and type="tel" are checked automatically. Extra rules via data-validate: email phone password date futureDate location; data-match="#id" for password confirmation. Errors are announced and linked with aria-describedby and aria-invalid.

Options: data-success="message", data-redirect="page.html", data-keep (don't reset). Replace the timeout in initValidation() with a fetch() to Formspree, Netlify or your API.

Fleet filters

Cards in #fleetGrid carry data-type, data-fuel, data-transmission, data-seats, data-price, data-rental, data-trips and data-order. The form #fleetFilters filters them live; #fleetSort sorts by recommended, price or popularity. Simple category tabs anywhere use data-filter-group="#target" with data-filter buttons and data-filter-item children.

Dashboard charts

Charts are declared in HTML and drawn as SVG — no library required:

<div class="chart" data-chart="line" data-format="inr"
     data-labels="Jan,Feb,Mar"
     data-series='[{"name":"Revenue","values":[120,140,160]},
                   {"name":"Target","values":[130,130,150],"alt":true}]'
     role="img" aria-label="Revenue"></div>
<div class="donut-wrap" data-donut='[{"label":"Sedan","value":42}]'
     data-center="81%" data-sub="Utilised"></div>

data-chart is line or bar. Date-range buttons use data-range-for="#chartA,#chartB". To use live data, set the attributes from your API response and call KaarvanCharts.render(). To switch to Chart.js or ApexCharts, replace renderChart().

Integrations

  • Google Maps: map placeholders on booking, locations and contact contain commented embed code. Add your API key and replace the .map-placeholder element.
  • Payments: step 5 of the booking page marks where Stripe Elements and PayPal Smart Buttons mount. Card fields in the demo are not submitted anywhere.
  • Forms: contact uses a Formspree action and data-netlify="true"; keep whichever you use.
  • Newsletter: set the Mailchimp or ConvertKit endpoint in the action of form[data-newsletter] and post with fetch() in initNewsletter().
  • Auth: login and register post to /api/auth/* placeholders.

Images

All photos are served locally from assets/images/; no external image CDN is used. If an image fails to load, main.js shows a neutral branded placeholder so the layout never breaks. To swap a photo, replace the file in assets/images/ (or update the src in the HTML).

SEO

Each page has a unique title and description, canonical URL, Open Graph and Twitter tags and JSON-LD structured data. Replace https://www.kaarvan.example with your domain across all files, then submit sitemap.xml in Search Console.

Accessibility

Built toward WCAG 2.1 AA: semantic landmarks, skip link, single H1 per page, keyboard-operable tabs, menus and modals, labelled controls, accessible error messages, 44 px touch targets, AA colour contrast (use --k-amber-deep for amber text on light backgrounds), reduced-motion support and hidden data tables for charts.
